# **一、项目概述**
**灵山胜境 AI 数字人导游系统是一款面向无锡灵山胜境景区的智慧旅游解决方案。系统以 Live2D 数字人“小灵”为交互形象，融合 DeepSeek Chat 大模型对话能力、GPT-SoVITS 语音合成技术、腾讯地图与 ECharts 数据可视化，构建游客端智能导览与景区运营管理的完整闭环。**
## **建设背景**
**灵山胜境是无锡乃至长三角地区重要的佛教文化旅游目的地，年接待游客量超过 380 万人次。随着游客对智能化、个性化服务需求的提升，传统人工导览模式面临成本高、覆盖有限、信息更新慢等瓶颈。本项目通过 AI 数字人技术，为每一位游客提供 7×24 小时在线、随时可问、所见即所得的沉浸式导游服务。**
## **产品愿景**
**让每一位游客，都拥有专属的数字人导游。以“小灵”为核心载体，通过自然语言对话、个性化推荐、语音讲解与实时可视化导览，提升游客体验与景区运营效率。**

# **五、AI 对话与 RAG 知识增强**
**系统 AI 对话采用“检索增强生成”（RAG）机制，避免大模型幻觉，确保回答基于景区真实知识。对话流程如下：**
**关键词提取：对用户问题进行分词和停用词过滤。**
**景点信息检索：从 scenic_spots 表获取全量景点信息。**
**FAQ 检索：对 faqs 表进行关键词匹配检索。**
**知识库文档检索：对 knowledge_documents 表进行 LIKE 查询。**
**上下文组装：整合景点、票务、FAQ、文档，限制 5000 字符。**
**System Prompt 构建：注入个性化偏好与最近 10 轮对话历史。**
**DeepSeek Chat 调用：模型 deepseek-chat，temperature 0.7，max_tokens 2000。**
## **个性化偏好注入**
**当游客在个性推荐模块选择兴趣标签（如“历史文化、佛教艺术”）后，系统会在 System Prompt 中插入【游客个性化偏好 - 务必遵循】段落，指导 AI 侧重景点历史沿革、文化内涵、文物故事，优先推荐与偏好相关的景点和活动。**
## **降级兜底策略**
**当 DeepSeek API 不可用（网络异常、密钥失效）时，系统自动降级为本地关键词匹配兜底回复，返回预设的票务、景点基础信息，并提示游客联系景区客服。该机制确保系统在网络波动时仍可回答基础问题。**

# **六、Live2D 数字人“小灵”**

| **项目** | **规格** |
| --- | --- |
| **模型名称** | **小灵（ling）** |
| **模型文件** | **ling.moc3 + ling.model3.json** |
| **物理模拟** | **ling.physics3.json（头发、衣物摆动）** |
| **表情数量** | **8 种：normal / smile / angry / sad / surprise / think / shy / cry** |
| **动作数量** | **2 组：眨眼（zhaiyan）、照相（zhaoxiang）** |
| **口型同步参数** | **ParamMouthOpenY** |
| **贴图数量** | **2 张** |

**系统支持 12 种情绪触发词（happy、sad、excited、surprise 等）到 Live2D 表情的映射。AI 回复经情绪识别后，自动触发对应表情，并配合 GPT-SoVITS 合成的音频进行口型同步。口型同步基于 Web Audio API 提取 WAV 音频振幅，实时映射到 Live2D 的 ParamMouthOpenY 参数，灵敏度、平滑系数、振幅阈值均可在后台配置。**

# **七、TTS 语音合成引擎**
**TTS 模块采用子进程隔离架构。GPT-SoVITS 作为独立 Python 进程运行，通过 stdin/stdout 与 Express 服务器通信。这种设计保证了主服务与 TTS 引擎的故障隔离：即使 TTS 进程崩溃或重启，也不会影响游客导览、管理后台等核心功能。**
## **通信协议**
**请求（stdin）：JSON + 换行，例如 {"text": "欢迎来到灵山胜境", "text_language": "zh"}。响应（stdout）：4 字节长度（UInt32LE）+ WAV 音频数据；当长度为 0 时，后续内容为 UTF-8 错误信息。**
## **性能对比**

| **模式** | **推理速度** | **硬件要求** |
| --- | --- | --- |
| **GPU 加速** | **约 6.5 秒/句** | **NVIDIA 显卡 + CUDA 12.x + PyTorch GPU 版** |
| **CPU 推理** | **约 64 秒/句** | **无特殊依赖，PyTorch CPU 版** |

# **八、数据层设计**
**系统采用 SQLite 嵌入式数据库，开启 WAL 模式与外键约束，共 13 张表，按业务类型分为 4 类：**

| **分类** | **表名** | **说明** |
| --- | --- | --- |
| **景点类** | **scenic_spots / highlights / tips** | **景点主表 / 亮点 / 贴士** |
| **路线类** | **routes / route_stops** | **游览路线主表 / 路线站点** |
| **交互类** | **faqs / chat_interactions / character_configs / visitor_stats / visitor_behavior** | **常见问题 / AI 对话记录 / 数字人配置 / 景点访问统计 / 游客行为记录** |
| **运营类** | **ticket_info / admin_users / knowledge_documents** | **票务信息 / 管理员账户 / 知识库文档** |

**WAL 模式：读写不阻塞，写入性能提升 2-3 倍。**
**外键级联：删除景点时自动清理亮点、贴士、访问统计。**
**预编译语句：better-sqlite3 的 PreparedStatement 复用，防止 SQL 注入。**
**事务批量操作：db.transaction() 保证原子性。**

## **真实摄像头 + 场景识别**
**AR 导览调用设备真实摄像头，默认强制使用后置摄像头（facingMode: environment），并在右下角提供「⟲」切换按钮，可一键在前置/后置之间切换。**
**摄像头：navigator.mediaDevices.getUserMedia，实时实景画面。**
**定位：navigator.geolocation.watchPosition 持续获取 GPS 坐标。**
**方向：DeviceOrientationEvent 获取手机朝向，iOS 13+ 自动请求权限。**

## **AR 实景导览技术要点**

| **能力** | **技术方案** |
| --- | --- |
| **摄像头** | **getUserMedia({ video: { facingMode: 'environment' } })** |
| **定位** | **navigator.geolocation.watchPosition()** |
| **方向** | **deviceorientation / deviceorientationabsolute** |
| **距离计算** | **Haversine 公式** |
| **方位计算** | **经纬度方位角公式** |
| **前后切换** | **停止当前流后重新申请相反 facingMode** |
| **权限提示** | **检测 window.isSecureContext 并给出 HTTPS 引导** |
| **缓存刷新** | **升级 query 版本号 + Service Worker cache 版本** |
